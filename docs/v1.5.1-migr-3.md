# v1.5.1 migr-3 작업 리포트

## 결과

- 브랜치 `feat/v1.5.1-migr-3`
- 모드 코드는 바꾸지 않았다. Keyboard 빌드와 DLL 복사는 하지 않았다. 게임 `Mods`의 DLL은 migr-1 산출물 그대로다.
- 13:40 실행 로그 `MelonLoader\Latest.log`에서 다시 실패했다. 모드 해시 `19F6A0745B4962127159A4EC4B1380CE622806EC17BE65F87BC2A4278F875642`가 로드된 뒤 `UnityEngine.CoreModule`이 거부됐다.
- 오류는 `BadImageFormatException: Duplicate type with name '<>O'`이고, 이어서 `No Support Module Loaded`가 찍혔다.
- 어셈블리 생성은 이번 실행에서 다시 돌았고 성공으로 끝났다. `Config.cfg`의 `GameAssemblyHash`는 설치된 `GameAssembly.dll` SHA512 `526F4AFA67253B22A11FC0A55236EFE5F6211E57AA4E9999B6FB0E7A298DF5E6843A70CF642F691971D00156FE833437156464EDA4E76919FBA36D67FF23A1D4`와 같다. 다음 실행은 같은 게임 빌드라면 재생성을 건너뛴다.

## 원인

MelonLoader 0.7.3 Open-Beta는 net6로 모드를 로드한다. net6는 한 어셈블리 안에 이름이 `<>O`인 중첩 타입이 둘 이상이면, 부모가 달라도 로드를 거부한다. .NET 10에서는 같은 파일이 로드된다.

생성 직후 개수:

- `UnityEngine.CoreModule.dll`: 6개. 부모는 `Awaitable`, `ScriptPlayableBinding`, `ShaderKeywordSet`, `SpriteAtlasManager`, `CrashReport`, `TexturePlayableBinding`. 메서드와 필드는 없다.
- `UnityEngine.UIElementsModule.dll`: 32개.

다른 어셈블리의 `TypeReference` 중에 이름이 `<>O`인 것은 없다.

## 로컬에서 한 일

생성된 DLL은 저장소에 넣지 않는다. `tools/fix-il2cpp-angle-o.ps1`로 두 파일의 `<>O`를 `<>O_1`부터 고유 이름으로 바꿨다. 원본은 같은 폴더의 `.bak`에 있다.

net6 `Assembly.LoadFrom` 결과:

- `UnityEngine.CoreModule.dll`: 로드 성공
- `UnityEngine.UIElementsModule.dll`: 로드 성공

게임을 이 세션에서 다시 실행하지는 않았다. 지원 모듈이 붙는지는 다음 실행 로그로 확인한다.

## 다음 순번

- 게임을 다시 실행하고 `MelonLoader\Latest.log`에서 `No Support Module Loaded`가 사라졌는지 본다.
- 게임 업데이트로 Il2Cpp 어셈블리가 다시 생성되면 `tools/fix-il2cpp-angle-o.ps1`을 다시 실행한다.
